# Журнал действий · 03.10.2026

В Render Logs искать `AUDIT`. Это JSON с временем UTC. Для Самары прибавить 4 часа.
`visitor_id` — анонимная сессия браузера, не имя человека; `request_id` — серверный запрос;
`job_id` — задача. По ним искать связанные строки. Заголовок ответа X-Request-ID содержит номер запроса.

Сайт: открытие/уход со страницы, кнопки, ссылки, отправка формы, наличие ошибки браузера.
Основные кнопки имеют фиксированные имена (birth_details_send, location_confirm,
payment_start, report_open, microphone_toggle). Остальные — порядковый номер элемента;
его можно сопоставить с разметкой страницы той же версии.
События браузера — сообщения клиента, не доказательство завершённого расчёта.

Движок: начало/окончание HTTP-запросов, длительность, статус и безопасный код причины;
WebSocket — границы соединения, не содержимое речи. Дневной прогноз: принятие задачи,
машинный расчёт, трактовка, сборка HTML, результат; вызов Groq/Gemini, выбранная модель,
токены и оценка стоимости. Классика/срок/книга — фоновая задача и её результат;
прямые потоки наследуют контекст. Внутренние ThreadPoolExecutor и задачи после рестарта
не гарантируют сохранения visitor_id/request_id; job_id у отмеченных работников сохраняет связь.
Голос пишет выбранную модель, фактическая ротация провайдера остаётся в прежних логах.

Причины ошибок представлены классом исключения и кодом, без сырого ответа провайдера.
Этот журнал не объясняет психологическое намерение посетителя. Не пишет поля форм,
переписку, даты рождения, координаты, email, IP, пароли, query string и ключи доступа.
Прежние логи приложения остаются отдельными; это не аудит их исторического содержимого.

До 120 клиентских событий на сессию/загрузку страницы; сервер также ограничивает частоту.
Блокировщик, отсутствие сети или выключенный JavaScript могут пропустить события.
Журнал не вызывает ИИ и не меняет расчёт/промпты/платёжную логику. Есть дополнительный
сетевой трафик и обычный объём Render Logs. История хранится по действующим условиям Render;
вечный архив и отдельное хранилище этим изменением не создаются.

Проверка: 156 тестов движка; 184 проверки файлов сайта; Node-проверка отсутствия
личных данных в telemetry, именования кнопки, сохранения тела реального запроса и visitor_id.
Четыре последовательных прохода одной модели: реализация; независимая проверка изменений
(исправлено попадание подключения в HTML-строки JS, порядок middleware и перенос контекста);
проверка границ/личных данных; итоговая сверка и повторные тесты. Полная пользовательская
оплата и длинный платный разбор на сервере не запускались ради проверки журнала.
